# 짧고 일관된 주석 쓰기

주석이 길면 읽지 않는다. 안 읽히는 주석은 없는 것보다 나쁘다 — 자리를 차지하고
낡아서 거짓이 된다. 아래 규칙은 그것을 막기 위한 것이다.

작성할 때도, 남의 주석을 다듬을 때도 같은 규칙을 쓴다.

바탕에 깔린 태도는 하나다 — **공문서처럼 쓴다.** 같은 형식과 스타일을 반복하고,
차이를 둬야 할 부분만 다르게 쓴다. 읽는 사람은 틀을 한 번만 익히면 되고,
그 다음부터는 달라진 곳만 본다. 개성은 필요 없다.

핵심만 남긴다. 덧붙이고 싶을 때마다 그것이 차이인지 장식인지 먼저 가른다.

## 1. 길이는 주변에서 배운다

상한을 숫자로 정하지 않는다. 대신 **같은 종류의 이웃 주석을 먼저 읽고 그 규격 안에
머문다.** 함수 문서 주석이 다들 한 줄 설명 + 인자 목록이면 내 것도 그래야 하고,
파일이 원래 장문 서술을 쓰면 그건 그 파일의 규격이다.

내 주석이 이웃보다 길면 그것이 신호다. 셋 중 하나다.

- 다른 곳에 이미 적힌 사실을 반복한다
- 코드가 스스로 말하는 것을 옮겨 적는다
- 폐기한 대안을 변호한다

먼저 같은 파일을 검색해 이미 적힌 사실이 있는지 확인한다. 있으면 그쪽을 가리키지도
말고 그냥 쓰지 않는다.

## 2. 쓰지 말아야 하는 것

**설계가 바뀌면 거짓이 되는 사실.** 특정 테이블 값, 호환성 표의 한 칸, 상수값을
주석에 박으면 그 표가 바뀌는 순간 거짓말이 된다. 왜 이렇게 짰는지는 남기되,
어떤 값이라서 이렇게 된다는 서술은 남기지 않는다.

**버려진 실험.** 시도했다가 되돌린 접근, 검토 후 기각한 대안, "왜 X를 하지 않았는가"는
적지 않는다. 코드는 현재 상태만 설명한다. 그 논의는 커밋 메시지나 리뷰 회신에 둔다.

**코드를 다시 읽어주는 문장.** `i++` 위에 "i를 1 증가"는 쓰지 않는다.

예외 — **미래에 되돌려질 위험이 있는 결정**은 남긴다. 그게 없으면 다음 사람이
"단순화"하면서 같은 결함을 되살린다. 단 값이 아니라 이유를 쓴다.

여기서 "값" 은 **설계가 바뀌면 거짓이 되는 것** 을 말한다. 복잡도나 비용의 규모는 값이 아니라
이유의 일부다 — 어떤 방식을 왜 안 썼는지 적을 때는 **그 방식이 무엇을 하는지와 그래서 얼마가
되는지를 함께** 적는다. "끝까지 순회한다" 만 적으면 그게 문제인지 알 수 없다.

## 3. 줄바꿈 — 코드 주석에만 해당

이 절은 **소스 파일 안의 주석** 규칙이다. 코드에 줄 길이 제한(예: 120자)이 있어서
어차피 끊어야 하기 때문에, 이왕 끊을 거면 어디서 끊을지를 정하는 것이다.

**마크다운 문서에는 적용하지 않는다.** md 는 길이 제한이 없고 렌더러가 알아서 접으므로
하드랩하지 않는다 — 문단 하나가 한 줄이다. 손으로 접으면 문장을 고칠 때마다 다시 접어야
하고, diff 가 내용과 무관하게 흔들린다.

아래는 주석에 적용한다. 절 단위로 끊는다. 문장이 이어지는 중간에서는 끊지 않고,
의미가 나뉘거나 쉬어갈 수 있는 곳에서 끊는다.

```
나쁨:  The UPDATE deletes the old index entry, so the check cannot decide yet
       and waits out the transaction.

좋음:  The UPDATE deletes the old index entry,
       so the check cannot decide yet and waits out the transaction.
```

최대폭까지 채울 의무는 없다. 폭을 맞추려고 어색한 자리에서 넘기느니
짧은 줄로 둔다. 가독성이 폭보다 우선이다.

`--`, `:`, `->` 같은 구분 기호 **앞뒤에서 끊지 않는다.** 기호는 줄 중간에 둔다.

## 4. 문형 통일 — 공통 부분을 최대화

여러 항목이 나열되면 **차이만 눈에 들어오게** 만든다. 공통 부분이 많을수록 좋다.
축약보다 구조 일치가 우선이다. 짧게 만들려고 문형을 깨뜨리지 않는다.

```
나쁨:  T1 child FK-column UPDATE holds WX_LOCK on the child row
       T1 holds X_LOCK on its own MVCCID self-lock
       T2 waits with S_LOCK on that self-lock
       one transaction aborted once the deadlock was detected

좋음:  T1 holds WX_LOCK on the child row
       T1 holds X_LOCK on the self-lock
       T2 waits with S_LOCK on the self-lock
       T1 or T2 aborts after deadlock detection
```

리소스·주체·동작의 표현을 고정하면 꼬리가 겹치고 차이가 도드라진다.
문형이 몇 가족으로 수렴하는지 세어본다. 셋 이상이면 통합할 여지가 있다.

## 5. 같은 대상은 같은 문구로

한 대상을 목록·제목·출력 세 곳에서 지칭하면 문구를 동일하게 쓴다. 기호만 바꾼다
(`->` / `--` / `:`). 달라지면 읽는 사람이 다른 것인지 의심한다.

블록 단독으로 읽어도 이해되게 자립시킨다 — `same, but ...`보다 `same as C19, but ...`.

**거꾸로도 지킨다 — 같은 낱말을 서로 다른 대상에 쓰지 않는다.** 두 대상이 같은 낱말로
불리면 나오는 자리마다 어느 쪽인지 되짚어야 한다. 수식어를 붙여 가르거나 한쪽의 이름을
바꾼다. 앞에서 수식어를 붙였으면 뒤에서도 붙인다.

**제목은 그 블록이 무엇을 하는지 말한다.** "추가 사정" 은 뭔가 더 있다는 말만 하고
그게 뭔지는 하지 않는다. "빈 결과 신호를 플래그로 옮긴다" 로 쓴다.

반대쪽 실패도 있다 — 다 말하려다 욱여넣는 경우. 제목에 명사를 세 개 넘게
이어 붙이면(A의 B C D) 무엇이 무엇을 하는지가 순서로만 표시되고 조사가
빠져 관계가 안 보인다. 적어도 하나는 조사(가/이/를/의)로 살려 주어와
목적어를 드러내고, 마지막 명사가 동작이면 명사형(-ㅁ/-음) 대신 동사형
(-ㄴ다/-된다)으로 끝맺는다.

```
나쁨:  분할 태스크의 오버플로 append 실패 삼킴
좋음:  분할 태스크가 오버플로 append 실패를 삼킨다
```

## 6. 모호한 용어는 역할을 병기

도메인 용어가 반대 뜻으로 읽힐 수 있으면 구체 역할을 괄호로 붙인다.

```
Referencing (child) row still being deleted.
```

용어를 아는 사람과 모르는 사람 모두에게 통한다. 용어 자체가 틀렸으면 고친다 —
인접한 두 곳이 같은 대상을 반대로 부르는 상태를 남기지 않는다.

### 비유어는 쓰지 않는다

동작은 **그 동작의 기술 용어** 로 쓴다. 비유는 읽는 사람마다 다르게 해석되고,
검색으로 코드와 이어지지 않는다.

| 자주 새는 비유 | 대체어 |
|---|---|
| 굽다 / 구워진 | 변환한다 / 변환된 |
| 앉히다 / 앉은 | 설정한다 / 저장된 |
| 도장을 찍다 | 값을 설정한다 |
| 찍다 (출력 문맥) | 출력한다 |
| 기억하다 / 기억 | 캐시한다 / 보관한다 — 무엇에 매달린 무엇인지까지 |
| 걷다 / 걸어간다 | 순회한다 (자료구조), 스캔한다 (바이트열) |
| 누르다 (부하 문맥) | 부하를 준다 |
| 태우다 (경로 문맥) | 그 경로로 실행한다 |

## 7. 주장과 검증을 일치시킨다

메시지나 주석이 **검증하지 않은 것을 주장하면 안 된다.** 문형을 맞추려고 거짓을 쓰는
것보다 차이를 남기는 편이 낫다.

```
tran_waits 는 대기 모드를 검사한다   -> "waits with S_LOCK on the self-lock"
row_blocked 는 대기자 존재만 본다    -> "waits on the parent row"    (with <MODE> 없음)
```

## 8. 서식은 파일에서 읽어온다

간격, 정렬 열, 구분선 폭, 목록 기호 — 파일이 이미 쓰는 방식을 그대로 따른다.
새 규칙을 들여오지 않는다. 규칙이 보이지 않으면 가장 가까운 이웃을 복제한다.

## 9. 분석 문서에 추가로

- **확인된 것과 추정을 분리한다.** 표로 나누고 근거를 적는다
- **출처를 표시한다.** 직접 실측 / 남의 보고 / 코드 읽기 / 추론을 구분한다
- 미검증 칸은 비워두지 말고 미검증이라고 쓴다
- 상충하는 정보가 있으면 숨기지 말고 상충한다고 쓴다
- ASCII 다이어그램은 ASCII 문자만 (`-` `|` `+` `>` `<` `/` `\`), 라벨은 영어
- **표로 쓸 수 있는 것은 코드 블록에 넣지 않는다.** 코드 블록은 코드·의사코드·구조
  다이어그램용이다. 열이 있는 데이터를 공백으로 맞추면 값이 바뀔 때마다 다시 정렬해야 하고,
  렌더러가 해 줄 일을 손으로 하는 셈이다

## 다듬을 때의 절차

1. 같은 종류의 이웃보다 긴 주석 블록을 찾는다
2. 각 블록에서 다른 곳에 이미 있는 문장을 지운다
3. 설계 결합·버려진 실험 언급을 지운다
4. (주석만) 남은 것을 절 단위로 다시 줄바꿈한다. md 는 건너뛴다
5. 나열된 항목들의 문형을 맞춘다 — 공통 부분 최대화
6. 같은 대상의 여러 표기를 하나로 통일한다
7. 비유어를 찾아 기술 용어로 바꾼다 (6절 표)
8. 파일의 기존 규칙(간격, 정렬, 구분선 폭)에 어긋난 곳을 찾는다

한 번에 끝나지 않는다. 2~5를 몇 차례 반복하면 매번 새로 걸리는 것이 나온다.
