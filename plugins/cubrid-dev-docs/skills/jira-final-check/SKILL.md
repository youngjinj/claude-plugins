# JIRA 문서 최종 점검

초안 내용을 다듬는 것과, 그 초안을 밖으로(JIRA, PR, 공유 채널) 내보내도 되는지
점검하는 것은 다른 일이다. `debate-cuts` 가 전자(필요한 내용만 남기기)라면,
이 스킬은 후자다 — 내용은 맞아도 이 문서 밖으로 나가면 안 되거나 뜻이 안 통하는
것을 걸러낸다.

## 쓰는 법

1. 아래 규칙을 하나씩 문서에 대조한다.
2. 규칙을 어긴 부분을 찾으면, 그 규칙의 "판단이 애매하면" 지침을 따른다 —
   대개 "확실하면 고치고, 애매하면 사용자에게 물어본다"이다. 임의로 삭제하거나
   임의로 남겨두지 않는다.
3. 점검 결과를 사용자에게 짧게 보여준다 — 어떤 규칙에 걸렸고 어떻게 처리했는지.
4. 사용자가 "이것도 규칙으로 넣자"처럼 새 점검 항목을 제시하면, 아래 목록에
   같은 형식(규칙 / 이유 / 판단이 애매하면)으로 추가한다. 기존 규칙을 고치거나
   빼지 않는 한 이 스킬은 계속 늘어나기만 한다.

## 규칙

### 1. 첨부되지 않을 파일 언급 금지

- **적용 범위**: 문서 머리에 "내부용" 선언이 있으면 이 규칙을 건너뛴다 —
  그 선언 자체가 "이 문서는 저장소 안에서만 보고, 실제 제출본은 따로 있다"는
  뜻이다(`jira-create-error`/`jira-create-imprv` 의 ISSUE.md 머리가 이렇게
  선언한다. README.md, HANDOFF.md 같은 문서는 관례상 항상 내부용이므로
  선언이 없어도 예외로 친다). 그런 선언이 없는, 실제로 밖으로 나갈 문서
  (JIRA 본문, ISSUE.jira, 외부 PR 설명 등)에만 이 규칙을 적용한다.
- **규칙**: 이 티켓과 함께 첨부되거나 별도로 공유될 계획이 없는 스크립트,
  md 문서, 기타 파일의 경로/이름을 본문에서 언급하지 않는다.
- **이유**: JIRA/PR 독자는 로컬 저장소나 작업 디렉터리에 접근할 수 없다.
  첨부되지 않는 파일을 가리키면 확인할 수 없는 참조만 남아, 근거로 쓸모가
  없거나 "찾아봤는데 없다"는 오해를 부른다.
- **판단이 애매하면**: 그 파일이 첨부될지 안 될지 확실하지 않으면 임의로
  지우지 말고 사용자에게 먼저 묻는다.
