CUBRID 문서를 0단계부터 4단계까지 순서대로 다듬는다. 원본 파일은 수정하지 않고 결과를 화면에 출력한다.

## 대상 문서

$ARGUMENTS

## 파이프라인

순서를 고정한다. 단계마다 변경 내역을 보고한다.

| 순서 | 스킬 | 무엇을 하나 |
|---|---|---|
| 0 | (없음) | 함수명·파라미터명·상수·설정값을 CUBRID 소스에서 `grep` 으로 확인 |
| 1 | (없음) | 구조 진단. 문제가 있으면 재배치를 **제안하고 승인을 받는다** |
| 2 | `grammar-checker`, `style-guide` | `references/style.md` 적용 → 맞춤법·띄어쓰기 → 용어·숫자·표기 일관성 + 용어집 대조 |
| 3 | (없음) | 용어·문체 후보를 **한 번에** 묻는다 |
| 4 | (없음) | 처음 보는 CUBRID 엔지니어가 던질 질문 5개를 뽑는다 |

## 0단계 — 검증

소스 경로와 리비전을 가진 워크트리 목록은 `references/repos.md` 가 갖는다.

리비전은 문서가 밝힌 것을 쓴다. 밝히지 않으면 여기서 묻는다. 체크아웃하지 않고 그 커밋의 트리에서 센다.

```bash
cd ~/github/develop
git grep -n '<패턴>' <리비전> -- src           # 예: f30f1c2 = 11.5.0.2374
git show <리비전>:src/connection/<파일> | sed -n '<줄>p'
```

- 없거나 철자가 다르면 **고치지 않고** `확인 필요` 에 올린다.
- 줄 번호가 적혀 있으면 그 줄에 무엇이 있는지 함께 확인한다. 리비전이 다르면 줄 번호가 어긋난다.
- `~/github/develop` 이 없으면 건너뛰고 건너뛰었다고 알린다.

## 1단계 — 구조

아래를 점검하고 **해당하는 것만** 보고한다. 문제가 없으면 `구조 이상 없음` 이라고 하고 2단계로 간다.

- 첫 문단이 `무엇을 왜 바꾸는가` 를 전달하지 못한다
- 성격이 다른 내용이 한 덩어리에 섞여 있다 (변경 제안 / 측정 계획 / 재현 절차)
- 같은 내용이 여러 절에 중복된다
- 주장만 있고 근거가 없다 — 비용·트레이드오프, 검토한 대안, Non-Goal 누락 포함
- 앞에서 정의되지 않은 개념이 먼저 등장한다
- 절 제목이 내용을 예고하지 못한다

문제가 있으면 **재배치하기 전에** 아래를 제안하고 승인을 받는다. 승인 없이 문장을 옮기지 않는다.

- 새 목차(안)
- 원문 각 단락이 어디로 가는지 매핑 (예: `효과/측정 관점` 세 번째 불릿 → 새 5장)
- 삭제 또는 통합 대상과 그 이유
- `-> [이대로 진행 / 일부만 / 현행 구조 유지]`

승인한 뒤 재배치할 때: **원문 문장을 옮기는 것을 우선한다.** 새로 쓰는 것은 연결이 끊기는 자리로 최소화하고 `[신규]` 로 표시한다. 삭제한 내용은 버리지 않고 따로 보여 준다.

## 2단계 — 문장

`references/style.md` 를 적용한다. 능동태, 코드 블록 언어 태그, 파라미터 표 형식, `에러 → 원인 → 조치` 구조를 포함한다.

`references/glossary.md` 와 대조한다. 용어집에 없는 용어 중 아래에 해당하면 3단계 후보로 모은다. **임의로 통일하지 않는다.** 사용자가 정하기 전까지 원문 표기를 그대로 둔다.

- 문서 안에서 표기가 흔들린다 (`bind 값` / `바인드 값`)
- 한글과 영문 중 무엇으로 쓸지 애매하다 (`broker` / `브로커`)
- 2회 이상 반복되는 기술 용어다

`style.md` 규칙과 원문이 충돌하는 자리도 문체 후보로 모은다.

## 3단계 — 확인

판정이 둘로 갈린다. **하나만 묻는다.**

| 판정 | 누가 정하나 | 묻나 |
|---|---|---|
| 영문 유지 / 한글 표기 | 팀 | **묻는다** |
| 한글로 쓸 경우의 철자 | 국립국어원 외래어 표기법 | 묻지 않고 알려만 준다 |

용어 후보와 문체 후보를 **한 번에 모아서** 묻는다. 하나씩 끊어 묻지 않는다. 선택지가 명확하면 `AskUserQuestion` 을 쓴다.

```text
용어: broker
문서 내 실제 표기: "broker" 12회, "브로커" 3회
한글 표기 시 철자: 브로커 (국립국어원 외래어 표기법)
-> [영문 broker / 한글 브로커 / 이번엔 보류]
```

- 확정된 것만 `references/glossary.md` (용어) 또는 `references/style.md` (문체) 에 **근거와 함께** 기록하고 문서에 적용한다.
- 용어 근거는 둘 중 하나다 — 국립국어원 외래어 표기법(철자만) / 팀 결정(날짜). TTA 와 CUBRID 매뉴얼은 자동 조회하지 않으므로 근거로 쓰지 않고, 필요하면 비고에 `미확인` 으로 남긴다.
- 보류한 것은 `references/skipped.md` 에 날짜와 함께 기록하고 이후 다시 묻지 않는다. 사용자가 `보류 목록 다시 검토` 라고 할 때만 꺼낸다.
- **결정 전에는 최종본을 출력하지 않는다.**

## 4단계 — 리뷰

이 문서를 처음 보는 CUBRID 엔지니어가 던질 질문 5개를 뽑는다. 문서가 답하지 못하는 질문은 `확인 필요` 에 추가한다.

## 상위 규칙

아래가 하위 스킬의 지시와 충돌하면 아래를 따른다.

- **기술적 사실, 수치, 함수명, 파라미터명, SQL 은 수정하지 않는다.** 틀린 것 같아도 고치지 않고 `확인 필요` 에 적는다.
- **영문 기술 용어는 번역하지 않는다.** `flush`, `bind`, `barrier`, `durability` 를 한글로 바꾸지 않는다.
- **국립국어원 `다듬은 말`(순화어)은 적용하지 않는다.** 코드 식별자와 문서 용어가 어긋난다 (`task force → 특별팀` 을 적용하면 `task_worker` 와 갈린다).
- **불릿의 병렬 구조는 의도된 것이다.** 항목들이 같은 문형인 것은 결함이 아니다.
- **Jira 마크업을 유지한다.** `h4.`, `*굵게*`, ` ```jira ` 블록을 깨뜨리지 않는다. 이미 있는 `{{코드}}` 도 깨뜨리지 않되 새로 만들지 않는다 — CUBRID Jira 인스턴스에서 렌더링되지 않는다(`issue-docs` 스킬 기록).
- **SQL 과 CLI 구문 표기를 유지한다.** `[ ]` 선택, `{ }` 필수, `|` 배타, `...` 반복.
- **문장·서식 규칙이 충돌하면 `references/style.md` 가 우선한다.**
- **원본 파일을 수정하지 않는다.** 결과는 화면에 출력한다.

## 출력 형식

해당 없는 항목은 `없음` 이라고만 적는다.

1. 구조 진단 결과. 재배치했다면 `[신규]` 문장 목록과 삭제된 내용을 함께.
2. 다듬은 전문.
3. 단계별 변경 내역. 무엇을 왜 바꿨는지.
4. 용어·문체 결정 내역 (추가 / 보류).
5. `확인 필요` — 기술적 사실로 보여 손대지 않았으나 확인이 필요한 자리.
6. 리뷰어 질문 5개.
